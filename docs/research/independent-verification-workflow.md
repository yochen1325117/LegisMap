# 立委資料獨立驗證流程

## 目的

獨立驗證流程用另一套搜尋方法重新發現及判斷事件，檢查主蒐集流程的漏件、錯誤歸屬、分類差異與程序狀態。驗證者提交前不能查看主流程的搜尋紀錄、候選事件、排除理由或事件文字。

本流程與[主蒐集流程](./research-pipeline-and-data-model.md)使用相同的研究期間及公開證據門檻，但保留獨立的搜尋、候選、版本與判斷紀錄。

## 角色與隔離

每批研究包含三個角色：

1. **主研究者**：執行人物導向搜尋並鎖定主流程版本。
2. **獨立驗證者**：在隔離狀態下執行來源及事件導向搜尋並鎖定驗證版本。
3. **裁決者**：雙方鎖定後查看差異、補查來源並作最終決定。

不同角色應由不同研究執行者或彼此隔離的執行環境負責。獨立驗證者提交前只能存取：

- 官方人物名單及姓名異體。
- 研究期間與公開研究規範。
- 自行搜尋到的公開原始來源。
- 自己建立的搜尋及候選紀錄。

獨立驗證者不能存取主流程的候選 ID、事件標題、來源清單、排除理由、查詢紀錄及版本內容。驗證紀錄也不能直接修改主流程資料。

## 獨立搜尋方法

主流程以人物姓名及事件類型組合為主；獨立流程改由來源及事件反查人物，降低兩套流程產生相同盲點的機率。

### 來源導向搜尋

- 逐一搜尋主要新聞媒體站內的五年報導。
- 分別搜尋法院、檢察署、監察院、審計部、中選會、政治獻金及立法院資料庫。
- 檢查政黨、本人、工會、公益組織及其他具名利害關係人的原始聲明。
- 每個年度分段查找，避免搜尋排序只呈現近期熱門內容。

### 事件導向搜尋

- 由法案、預算、司法案件、選舉、政治獻金及社群爭議等議題反查人物。
- 使用姓名異體、原住民族名、曾用名、英文名及常見誤寫確認身分。
- 對每個候選事件另行搜尋本人回應、相反觀點、程序進展及最終結果。
- 搜尋引擎摘要只能用於發現，事件證據必須來自可開啟及可定位的頁面。

每項查詢沿用主流程的深度規則：至少檢查前 20 個不重複結果；最後 10 個結果仍有新候選時，繼續至 50 個或連續 20 個沒有新候選事件。

## 鎖定與版本

- 主流程及獨立流程各自產生獨立 `versionId`。
- 搜尋、候選及決定紀錄在提交時寫入 `lockedAt`。
- 鎖定後不能原地修改；修正必須建立新版本並保留舊版。
- 系統只有在兩個版本均鎖定後才能開始差異比對。
- 獨立版本在鎖定前不得引用主流程候選 ID；驗證器應拒絕此類資料。

兩套流程找到同一來源並不構成違規。重點是獨立驗證者必須透過自己的搜尋發現來源，而非從主流程清單複製。

## 差異比對

版本鎖定後，以官方案號、人物、日期、來源 URL、標題實體及事件內容產生候選配對。不得只因標題文字相似就自動合併。

### `VerificationComparison`

```ts
type MatchStatus = 'matched' | 'primary_only' | 'independent_only' | 'possible_match';

type DifferenceType =
  | 'category'
  | 'member_attribution'
  | 'role'
  | 'date_or_scope'
  | 'process_status'
  | 'result_status'
  | 'evidence_level'
  | 'publication_threshold'
  | 'person_response'
  | 'resolution'
  | 'duplicate_resolution';

interface VerificationComparison {
  id: string;
  primaryCandidateId: string | null;
  independentCandidateId: string | null;
  matchStatus: MatchStatus;
  differenceTypes: DifferenceType[];
  comparedAt: string;
}
```

雙方找到相同事件且人物、角色、範圍、程序、結果及發布判斷一致時，可以進入正式發布層。主流程獨有、獨立流程獨有、可能相同或存在任何實質差異者，都必須送交裁決。

## 第三階段裁決

裁決者先檢查兩份鎖定紀錄，再視差異補查原始來源。裁決不得刪除或回寫任一方的原始資料。

### `AdjudicationRecord`

```ts
type AdjudicationDecision =
  | 'publish'
  | 'needs_more_evidence'
  | 'merge'
  | 'reject'
  | 'out_of_scope';

interface AdjudicationRecord {
  id: string;
  comparisonIds: string[];
  additionalSourceIds: string[];
  decision: AdjudicationDecision;
  reason: string;
  finalEventId: string | null;
  decidedBy: string;
  decidedAt: string;
}
```

裁決內容必須涵蓋：

- 雙方原始判斷與差異類型。
- 補查來源及頁面定位。
- 最終事件範圍、日期、人物與角色。
- 最終分類、程序、結果及證據強度。
- 發布、補證、合併、排除或超出範圍的理由。

`needs_more_evidence` 會讓人物停留在 `needs_followup`；其他實質差異在裁決完成前會讓人物停留在 `awaiting_adjudication`。

## 完成與品質指標

每位委員只有在下列事項全部完成後才可標記為 `complete`：

- 兩套搜尋矩陣均完成並鎖定。
- 所有候選均有比對結果。
- 所有實質差異均有裁決。
- 沒有未處理的證據或回應缺口。
- 正式來源已重新開啟並更新複核日期。

報告分別顯示：

- 主流程與獨立流程完成率。
- 候選事件重合率。
- 主流程獨有與獨立流程獨有事件比例。
- 分類、歸屬、程序與發布門檻的差異數。
- 已裁決、待裁決及待補證據數。
- 兩套流程各自的來源類型及年份覆蓋。

重合率低代表需檢查搜尋方法，不能直接解讀為任一方錯誤。事件數與正負比例不作研究者績效指標。

## 範例：吳思瑤宿舍貼文事件

以下範例說明雙軌流程，不預先指定兩邊必須得到相同結論。

### 主流程可能發現

- 以「吳思瑤 爭議」「吳思瑤 宿舍」「吳思瑤 澄清」找到 2026-08-31 起的報導。
- 建立候選事件，描述她在學生住宿開箱貼文下將住宿環境連結到「新宿舍運動」，學生後續澄清該處為私人租屋。
- 補足兩個獨立發布者，以及她表示不希望學生遭出征、事件失焦或造成對立的後續回應。
- 不將部分網友攻擊學生描述成她指示或組織的行為。

### 獨立流程可能發現

- 從 2026 年媒體政治新聞、學生住宿政策報導及「新宿舍運動」議題反查人物。
- 獨立確認貼文、租屋澄清、網路反應及本人後續說法。
- 另從立法院與教育政策資料確認「新宿舍運動」本身確有政策紀錄，避免把單次誤認擴張成整項政策不存在。

### 比對與裁決

- 若兩邊事件範圍與責任歸屬一致，可發布為「在校外租屋貼文下宣傳新宿舍運動引發爭議」。
- 若一方把網友攻擊歸因於本人，標記 `member_attribution` 與 `publication_threshold` 差異，交由裁決者查證。
- 若一方把 2018 年政策推動與 2026 年貼文合成單一事件，標記 `date_or_scope` 與 `duplicate_resolution` 差異。
- 裁決後應把政策問政紀錄與 2026 年貼文爭議分為不同事件；超出五年期間的原始 2018 行動不能直接作為本期事件，但可用於理解政策沿革。

## 驗證案例

- 第二流程在鎖定前引用主流程候選 ID：拒絕。
- 任一版本尚未鎖定便建立比對：拒絕。
- 雙方標題不同但官方案號、人物與日期相同：建立 `possible_match`，不得直接合併。
- 獨立流程發現主流程漏件：建立 `independent_only` 並送裁決。
- 雙方找到同一爭議但程序狀態不同：送裁決，不自動選擇較新或較嚴重者。
- 雙方均未找到事件：若搜尋矩陣及查詢深度完整，可以完成，並顯示截至查閱日尚無已核實資料。
